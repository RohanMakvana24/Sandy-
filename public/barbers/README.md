# Barber collection assets

The live cards now use `artist-01-front.svg` through `artist-04-front.svg`
with four unique AI-generated photographic cutouts (`portrait-01.webp`
through `portrait-04.webp`). The WebP portraits preserve transparent alpha.
Each SVG embeds its portrait, so Canvas/WebGL textures need no nested network
request. Corresponding `artist-XX-back.svg` artwork preserves the flip faces.
Prompts and generation provenance: `scripts/barber-portrait-prompts.json`.
These fictional models are previews, not photographs of actual salon staff.

The `preview-01` through `preview-04` SVG pairs are anonymous development
artwork, not real Sandy employees. They use 1024 × 1440 portrait proportions.
No approved reference image or real staff photographs were supplied.

Edit `src/utils/barbers.ts` to replace identities, specialties and face paths.
Replace each front/back pair with approved flat artwork. Leave space around
the physical attachment slot at the top. No illustrated rope is needed.
Regenerate the temporary artwork with `npx tsx scripts/generateBarberPreviews.ts`.

The integration reuses `src/components/Lanyard.jsx`, the existing React Bits
implementation: https://reactbits.dev/components/lanyard
Its physics and flip logic are preserved. Integration changes limit DPR to
1.5, stop hidden-tab/offscreen loops, report WebGL failure to the HTML fallback,
and allow native vertical touch scrolling. Olive fabric is generated by the
component; no external strap asset is required.

Desktop shows four cards; tablet shows two per row; mobile mounts only the
selected card's renderer. Reduced motion uses static artwork. Each profile's
HTML details exposes both faces and all information without a canvas.
